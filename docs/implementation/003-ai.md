# 003 — AI authoring

## Intention and goal

Connect generation, conversation, proposed revisions and analysis without surrendering teacher control.

## Scope and decisions

AI SDK with server-only OpenAI-compatible configuration. Versioned task prompts. Zod validates every structured result; one repair retry with validation feedback. Exact integer blueprint totals are enforced on generated papers. Existing questions replaced only on explicit generation confirmation and after atomic validation. Database generation lease plus exam revision check rejects duplicate or conflicting generation. Streaming chat persists completed responses only and marks interruptions. Structured proposals retain input revision, requiring explicit acceptance and conflict checks. Whole-paper analysis is advisory. AI logs omit credentials. Fixture mode is explicit and never automatic.

## Implementation

Provider adapter; deterministic fixtures; prompts; per-operation routes; run logging; question chat and proposal review UI; analysis findings with question links.

## Acceptance

Valid/invalid JSON, bounded repair, endpoint timeout/failure, missing setup, duplicate generation, aborted chat, proposal acceptance/staleness, run history, owner isolation.

## Outcome

Implemented a configurable AI SDK OpenAI-compatible adapter, explicit fixture adapter, versioned prompts, JSON/native structured-output modes, one repair attempt, exact mark-target checks, atomic replacement, duplicate-generation lease, persisted streaming conversations, before/after proposals, explicit acceptance with revision conflicts, and linked advisory paper analysis. AI history stores run metadata, validation errors, usage, results and input snapshots containing prior question history.

## Validation

Unit tests exercise missing configuration, explicit fixture mode, text/native structured output, malformed JSON, domain constraints, one-repair exhaustion, provider failure and conversation cancellation. Browser suites exercise generation, completed streaming chat, proposed/accepted revisions, stale proposal rejection, duplicate generation (one success/one conflict), cross-account denial, and review invalidation.

## Deviations and limitations

Streaming chat uses a small NDJSON transport over SDK text streams, rather than coupling database messages to a useChat wire format. Generation runs synchronously with a three-minute lease; no queue/worker. A process crash may leave a running run record, while the lease allows later recovery. Only completed assistant responses persist; interrupted partial text is labelled unsaved. Fixture content tests mechanics, not curriculum correctness. The live endpoint was not supplied, so live-provider interoperability and mathematical quality remain pending. History UI shows the latest 40 runs; all runs remain in SQLite. Manual deletion removes active question history; retained AI snapshots are not an immutable audit system.
